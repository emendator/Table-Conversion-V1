# 📊 表格转换工具（Table Converter）

## 项目简介

手头的表格往往来自不同渠道：列名不同、列序不同、格式不同，而你要把它们汇总进一份固定的标准模板。逐个复制粘贴既慢又容易出错，图片和公式更难处理。

本项目负责把这件事自动化，主要做三件事：

1. **读懂结构** —— 解析源表与模板的列结构，识别公式列、重复列名与内嵌图片；
2. **建立映射** —— 用「映射库 → 精确匹配 → AI / 本地语义匹配」三级策略确定列与列的对应关系；
3. **重建输出** —— 以模板为准生成结果工作簿：写入数据与公式、按锚点把图片搬到对应行，多份源表可合并为一个结果文件。

**适用场景**

- 周期性把多渠道、多来源的表格汇总到统一模板；
- 模板固定、来源多变，手工整理成本高；
- 希望在本机或内网离线处理（关闭 AI 后完全不需要联网）。

**不适用于**：在线协作编辑；需要完整保留源表原始样式（输出样式以模板为准）。

## 功能特性

### 列匹配

- **三级匹配策略**（与是否开启 AI 无关）：① 映射库中历史确认过的映射 → ② 列名完全相同的精确匹配 → ③ 剩余列交给 AI 或本地引擎；历史积累越多，需要 AI 处理的列越少、耗时越短
- **AI 语义匹配**：接入 DeepSeek，同时参考表头名称与列内实际数据来判断，可随时开关
- **本地匹配引擎**：字符相似度 + 领域关键词词典 + 数据类型推断综合评分，**无需联网**即可给出合理结果
- 匹配结果可**手动调整**：源列与目标列都能改，支持新增映射、删除映射，并显示匹配度
- **公式列标注**：源表或模板中的公式列会带 `ƒ` 标记，便于识别

### 映射库（映射历史）

- 手动调整过的映射关系会被自动记录，下次处理类似表格时优先使用
- 网页端支持搜索、编辑、删除单条记录，多选批量删除
- **导出**为 Excel，**导入** Excel / CSV（可选择覆盖现有库或合并写入；检测到重复源列名时弹窗确认：覆盖 / 跳过 / 取消）
- 每条记录显示来源（AI 自动 / 手动 / 导入）与使用次数

### 表格与图片处理

- **重复列名自动编号**：多列同名时按顺序编号（`金额`、`金额(2)`…），输出文件仍保留原始列名
- **公式列处理**：可针对源列 / 模板列分别选择「用数据 / 用源公式 / 保留模板公式 / 用数据覆盖」
- **图片精确搬运**：解析图片锚点后搬到结果表对应行并缩放居中，覆盖多种存储方式——`.xlsx` 的浮动锚点（drawings）、单元格内图片（`DISPIMG` / cellImages）、Office 365 richData，以及 BIFF8 `.xls`（WPS）的单元格内图片与 OfficeArt 锚点
- **图片错位提醒**：当 `.xls` 中的图片确实不含锚点信息时，会在上传后与转换完成时醒目提示建议另存为 `.xlsx`，不会静默产出错位结果
- **格式兼容**：普通 `.xlsx`、Office 365 另存的严格格式（OOXML Strict，自动转换后解析）、老式 `.xls`
- **上传自动去重**：同名或重复选择的文件只保留最新一份（前端按「文件名 + 大小」过滤，后端同步移除旧记录）
- **多文件合并**：一次上传多个源表，自动逐个匹配并合并为一个结果文件
- **结果预览与下载**：转换完成后可在页面上直接对比预览并下载 `.xlsx`

### 账号与数据

- 多账号登录 / 注册，并提供**游客登录**（免注册体验，退出后自动清除痕迹）
- 三级角色：最高级管理员 / 管理员 / 用户；通过**邀请码**注册，邀请码可指定注册账户的**有效期**
- 数据按**公司维度隔离**，同公司成员共享映射库，不同公司互不可见
- 账户、邀请码、API Key 等敏感数据**加密后落盘**，磁盘上不存明文

### 界面

登录页 Canvas 极光流体背景，以及磁性吸附、数字滚动、滚动进度、点击涟漪、3D 悬浮卡片、光标追光等动效；所有动效尊重 `prefers-reduced-motion`，触屏设备自动降级。

## 快速开始

### 环境要求

- **Python** 3.9 及以上（(待补充：最低支持版本)；开发环境实测 3.14）
- **Node.js** LTS（开发与部署脚本使用 Node 20）
- **Windows 一键启动** 需要 PowerShell 5.1+（Windows 10/11）；其它系统请用「手动启动」

### 方式一：Windows 一键启动（推荐）

双击项目根目录的 **`启动.bat`**，脚本会自动完成：检测 Python / Node → 创建并修复 `.venv` → 安装 pip 与 npm 依赖 → 启动后端与前端 → 打开浏览器。

- 启动窗口按任意键即可停止全部服务
- 若双击无反应，右键选择「以管理员身份运行」

### 方式二：手动启动

```bash
# 1) 后端（FastAPI）
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows 使用 .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8004

# 2) 前端（另开一个终端）
cd frontend
npm install
npm run dev
```

打开浏览器访问 **`http://127.0.0.1:3002`**。

> ⚠️ 登录会话保存在后端进程内存中，请以**单 worker** 方式运行（部署脚本已固定 `--workers 1`）。

### 首次使用

1. 进入登录页，可用**游客身份**直接体验，或使用邀请码注册账号；
2. 首次启动后端时会创建内置最高级管理员，**用户名与随机口令会在后端启动日志中打印一次**（也可通过环境变量 `TC_ADMIN_PASSWORD`、`TC_ADMIN_COMPANY`、`TC_ADMIN_COMPANY_DB_PWD` 预先指定），请立即登录并修改口令；
3. 点击右上角 **「⚙️ API 设置」** 填入自己的 DeepSeek API Key（`sk-` 开头）后即可使用 AI 匹配；不填则使用本地匹配引擎；
4. (待补充：在线演示地址)；
5. (待补充：界面截图 / 演示 GIF)。

## 使用流程

### 第一步：上传文件

页面上有两个上传区域：

| 左侧 | 右侧 |
| --- | --- |
| **原始表格** | **参考模板** |

拖拽文件到对应区域，或点击区域选择文件。左侧支持一次多选，也可后续点击「➕ 添加文件」追加；上传后显示各文件的行数 / 列数，可单个删除或一键清空。

> ⚠️ **表头要求**：首行必须是无合并单元格的表头，否则列匹配可能不准。
>
> ⚠️ 上传 `.xls` 时若其中图片缺少锚点信息，文件列表下方会出现黄条提醒，建议「另存为 `.xlsx`」后重新上传。
>
> 💡 模板只需上传一次，所有源表都按该模板转换；同名或重复文件会自动去重。

### 第二步：智能列匹配

1. 选择匹配方式：打开「使用 DeepSeek AI 匹配」使用语义匹配，关闭则使用内置本地引擎；
2. 点击 **「🔍 开始匹配」**，系统同时分析表头与列内数据完成配对；
3. 匹配完成后展示映射表（匹配度 / 源列名 / 目标列名 / 操作）。

### 第三步：检查与调整

- 匹配有误时用下拉框改目标列；漏掉的列点「➕ 手动添加映射」补充；多余的映射可删除；
- 源列名与目标列名都可以切换；
- **公式列处理**（仅涉及公式列时出现）：

  | 情况 | 可选处理方式 |
  | --- | --- |
  | 仅源列为公式列 | 用源数据（取计算值）/ 用源公式（保留计算公式） |
  | 仅模板列为公式列 | 保留模板公式 / 用数据覆盖 |
  | 两列均为公式列 | 保留模板公式 / 保留源公式 |

- **重复列名**会按顺序编号显示，输出文件仍保持原始列名。

### 第四步：执行转换

点击 **「🚀 开始转换」**，完成后可下载结果文件，也可在页面上预览。

### 第五步：检查结果

打开下载的 `.xlsx`，确认数据填入正确列、图片显示正常、公式列正常计算；不满意可点「🔄 转换新文件」重新开始。

## 配置说明

### 网页端配置（推荐）

| 配置项 | 位置 | 说明 |
| --- | --- | --- |
| DeepSeek API Key | 右上角「⚙️ API 设置」 | 加密后按账户保存，页面只显示掩码（如 `sk-****abcd`）；token 消耗按账户独立统计 |

### 文件配置

用编辑器打开 `backend/config.py`：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | 模型名称，可选 `deepseek-v4-flash`（更快）/ `deepseek-v4-pro`（更准） |
| `DEEPSEEK_API_URL` | `https://api.deepseek.com/chat/completions` | API 地址 |
| `IMAGE_ROW_HEIGHT_PT` | `60` | 结果表中图片所在行的行高（磅），调大图片更大、行更高 |
| `IMAGE_MARGIN_PT` | `4` | 图片与单元格边框的间距 |

### 环境变量

| 变量 | 作用 |
| --- | --- |
| `TC_ADMIN_PASSWORD` | 内置最高级管理员的初始口令；不设置则首次初始化时随机生成并打印 |
| `TC_ADMIN_COMPANY` | 内置最高级管理员所属公司名，默认「默认公司」 |
| `TC_ADMIN_COMPANY_DB_PWD` | 该公司的初始数据库密码；不设置则随机生成 |

### 参考模板

在网页上直接上传即可。公式列、数据列等结构全部由工具从模板中自动识别，**不存在硬编码的列映射规则**，更换模板不需要改代码。

## 命令行用法

除网页界面外，也可以直接用命令行批量处理（复用与网页端完全相同的转换逻辑）：

```bash
# 单个文件
python backend/main.py 路径/参考模板.xlsx 路径/源表.xlsx

# 多个源表（合并为一个结果文件）
python backend/main.py 路径/参考模板.xlsx 路径/源表A.xlsx 路径/源表B.xlsx

# 不使用 AI，仅用本地匹配引擎
python backend/main.py 路径/参考模板.xlsx 路径/源表.xlsx --no-ai

# 指定输出文件（仅单文件时有效）
python backend/main.py 路径/参考模板.xlsx 路径/源表.xlsx -o data/输出/结果.xlsx

# 单独设置并加密保存 DeepSeek API Key
python backend/main.py --set-api-key sk-xxxxxxxx
```

> 💡 命令行模式适合定时任务或脚本化批量处理；`--no-ai` 无需网络连接。

## 数据与隐私

所有运行数据集中在项目根目录的 `data/` 下（该目录已在 `.gitignore` 中排除，删除后会在下次启动时自动重建）：

| 路径 | 内容 |
| --- | --- |
| `data/users/` | 账户、邀请码、API Key、公司信息（加密存储） |
| `data/.ai_secret` | 本地加解密密钥文件，**请勿提交到 Git，也勿外传** |
| `data/映射历史记录_{key}.json` | 映射匹配库，按公司隔离键分文件，明文 JSON，可直接查看、备份或删除 |
| `data/uploads/` | 上传的临时文件 |
| `data/输出/` | 转换结果输出目录 |

**清理策略**：后台线程每 **5 分钟**清理一次 `data/uploads/` 与 `data/输出/` 中超过 **1 小时**的临时文件。

**游客模式**：不保留任何数据。退出登录、令牌过期（24 小时）或服务重启后，游客账号、映射库、API Key 以及本次上传 / 输出文件都会被自动清除。

> ⚠️ 请务必不要将 `data/` 目录或任何 API Key 提交到版本库；API Key 属于付费凭据，泄露后应立即吊销。

## API 概览

后端提供 REST JSON API，启动后可访问 `http://127.0.0.1:8004/docs` 查看自动生成的完整文档。按功能分为：

| 分组 | 主要路由 | 说明 |
| --- | --- | --- |
| 认证 | `/api/auth/*` | 注册、登录、登出、游客登录、当前用户 |

| AI 配置 | `/api/ai/config` | API Key 与 token 消耗信息 |

## 常见问题

**Q：上传后点击没反应？**
刷新页面（Ctrl+F5）；确认后端与前端两个服务都在运行，必要时重新执行启动脚本。

**Q：页面空白或提示端口无法访问？**
确认前端已启动并监听 3002 端口。`vite.config.js` 中已配置 `host: '0.0.0.0'` 以确保同时监听 IPv4，若仍失败请检查端口是否被占用。

**Q：AI 匹配返回 0 个列？**
多为网络问题导致返回不完整。可先关闭 AI 开关用本地引擎匹配，或确认能否访问 `https://api.deepseek.com` 后重试。

**Q：转换后图片位置不对或没有图片？**
工具按锚点精确归位，绝大多数文件都能正确处理。只有源 `.xls` 中图片完全不含锚点信息时才会按存储顺序放置，此时页面会醒目提醒——在 WPS / Excel 中另存为 `.xlsx` 后重新上传即可精确还原。

**Q：Office 365 保存的表格读不出数据？**
「严格 Open XML 格式（.xlsx）」已自动兼容（读取时转换命名空间后解析）。若仍有问题，用默认「Excel 工作簿」格式另存后重试。

**Q：表格里有同名列怎么办？**
会按出现顺序自动编号为 `金额`、`金额(2)` 以便区分；下载的输出文件仍使用原始列名。

**Q：模板里有公式列，转换后会破坏公式吗？**
不会。公式列会被自动识别，并由你选择「用数据 / 用源公式 / 保留模板公式」等处理方式。

**Q：映射历史记录存在哪里，可以清空吗？**
保存在 `data/映射历史记录_{key}.json`（按公司隔离键分文件，明文 JSON）。删除对应文件即可清空，下次使用时自动重建；也可在「映射匹配库」页面导出备份、导入恢复。

**Q：关闭 AI 后匹配效果如何？**
本地引擎通过列名语义、领域关键词与数据类型推断综合评分，对常见列名（序号、型号、价格、品牌、备注等）准确率较高；不准时可手动调整，调整结果会被记入映射库，后续自动优先使用。

**Q：多人同时使用会卡住吗？**
文件解析、转换与 AI 调用等耗时操作在线程池中执行，不会阻塞事件循环。若仍感觉缓慢，通常是机器内存或带宽不足。

## 部署

`deploy/` 目录提供了一套基于 Ubuntu + systemd + Nginx 的部署脚本：

```bash
cd /path/to/table-converter
sudo bash deploy/deploy.sh          # 默认监听 80 端口
sudo bash deploy/deploy.sh 8080     # 指定其它端口
```

脚本会安装系统依赖与 Node、创建 Python 虚拟环境、安装后端依赖、构建前端、配置 systemd 服务与 Nginx，并放行防火墙。更新时执行 `sudo bash deploy/update.sh`。

> ⚠️ 后端会话保存在进程内存中，systemd 单元固定为单 worker，请勿自行增加 `--workers`。
>
> 💡 部署前可用 `TC_ADMIN_PASSWORD` / `TC_ADMIN_COMPANY` / `TC_ADMIN_COMPANY_DB_PWD` 指定内置管理员凭据；未指定时首次启动会自动生成并打印在后端日志中。
